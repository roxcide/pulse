# PULSE — Brevo, Google и гостевой вход

Загрузи содержимое release/pulse-profile.zip в корень GitHub-репозитория. Deploy command: **pnpm run deploy**. Сборка и миграции выполняются автоматически. Существующую D1 pulse-db не удаляй.

## Если вход сообщает database_not_initialized

Это означает, что подключённая база не содержит всех необходимых таблиц или колонок. Для версии с админ-панелью нужны обе миграции: `0001_auth.sql` и `0002_admin.sql`.

1. Загрузи обновлённые файлы в GitHub, включая `scripts/deploy.mjs`, `scripts/deployment-plan.mjs` и папку `migrations`.
2. В Cloudflare → Workers & Pages → pulse → Settings → Builds установи Deploy command: `pnpm run deploy`. Прямой `npx wrangler deploy` пропускает миграции.
3. Запусти новую сборку актуального коммита. Теперь миграции и проверка схемы выполняются до публикации Worker. При их ошибке публикация остановится; смотри первую ошибку D1 в логе. Для токена сборки нужны права Account → D1 → Edit.
4. После успешного деплоя открой `https://pulser.pp.ua/api/auth/config`: ожидается `checks.database: "ready"`. Затем обнови страницу входа.

Если актуальный код уже опубликован, исправить базу отдельно можно из папки проекта после установки зависимостей:

```sh
pnpm exec wrangler login
pnpm run db:remote
```

Миграции сохраняют существующие аккаунты и тренировки. Не создавай новую базу вместо действующей и не повторяй вручную отдельные `ALTER TABLE`. Если команда не прошла, нужен текст первой ошибки миграции из лога, без секретов; один requestId не показывает, какой шаг не выполнен.

## Runtime variables and secrets

| Имя                  | Тип        | Значение                        |
| -------------------- | ---------- | ------------------------------- |
| APP_ORIGIN           | Variable   | https://pulser.pp.ua            |
| EMAIL_FROM           | Variable   | noreply@pulser.pp.ua            |
| BREVO_API_KEY        | Secret     | API-ключ Brevo                  |
| GOOGLE_CLIENT_ID     | Secret     | Client ID веб-приложения Google |
| GOOGLE_CLIENT_SECRET | Secret     | Client Secret того же клиента   |
| DB                   | D1 binding | pulse-db                        |

Если ключ уже добавлен, повторно вводить его не нужно: имя должно быть BREVO_API_KEY. Настройки нужны именно исполняемому Worker, не только сборке. keep_vars сохраняет переменные Dashboard при деплое. Cloudflare Email Sending и binding EMAIL не нужны.

В Brevo должны быть активны домен pulser.pp.ua и отправитель PULSE <noreply@pulser.pp.ua>. Подтверждённый DNS сам по себе не заменяет включённую транзакционную отправку аккаунта Brevo. Логи доставки доступны в Transactional → Logs.

## Проверка после деплоя

Открой https://pulser.pp.ua/api/auth/config. Ожидаются configured, passwordRegistration и passwordRecovery со значением true; checks.origin, checks.database и checks.email — ready. Это проверка конфигурации; доставку нужно проверить отдельным письмом.

1. Создай новый аккаунт с паролем от 8 символов. До подтверждения почты доступ к тренировкам аккаунта закрыт.
2. Введи на сайте шестизначный код из письма. Код действует 10 минут, максимум 5 попыток за 10 минут. Новый код заменяет предыдущий.
3. Аккаунт откроется автоматически, без повторного входа. Все личные показатели нового пользователя — 0.
4. Нажми «Не помню пароль», укажи свой email. Ссылка для нового пароля действует 30 минут, используется один раз и отзывает прежние сессии.
5. Если письма нет, проверь спам и Brevo Logs. Повторная отправка доступна раз в минуту, максимум пять раз в час на адрес.

Старым пользователям с неподтверждённой почтой при следующем входе будет предложена повторная отправка. Подтверждение привязано к браузеру, где начата регистрация. В другом браузере сначала введи email и пароль через «Войти», чтобы получить код. Если пароль забыт, используй сброс. Google и гостевой режим не зависят от Brevo. Данные гостя сохраняются только в браузере и не переносятся в аккаунт автоматически.

## Google

Authorized JavaScript origins: https://pulser.pp.ua

Authorized redirect URIs: https://pulser.pp.ua/api/auth/callback/google

Аккаунты Google и email/пароль автоматически не объединяются. Для Google-аккаунтов восстановление остаётся на стороне Google.

## Диагностика

- checks.database: missing_schema — выполни `pnpm run db:remote`, чтобы применить все оставшиеся миграции. Одного `0001_auth.sql` для админ-панели недостаточно. Данные не удаляются.
- checks.email: not_configured — проверь BREVO_API_KEY и EMAIL_FROM.
- email_configuration_error — Brevo отклонил настройки; проверь ключ, активность отправителя, доступ к транзакционным письмам и ограничения IP в Brevo.
- email_unavailable — временный сбой сети, лимит отправки или ошибка сервиса.
- invalid_code — код неверный или истёк. verification_expired — подтверждение в браузере истекло; введи email и пароль через «Войти».
- invalid_token — ссылка истекла, уже использована или отозвана; запроси новую.
- В остальных случаях смотри error и requestId в ответе API и Worker Logs. Содержимое секретов в логах отсутствует.

Сервер использует scrypt для паролей. Сохраняется требование достаточного CPU-бюджета Workers; подключение Brevo не меняет стоимость хеширования. Подробности в DEPLOY.md.

## Темы и гостевой режим

В настройках и на экране входа доступны PULSE, Mocha (мягкая тёмно-коричневая), Alduin, 80s After Dark и 8008. Dualshot удалена. Тема применяется сразу, включая кнопки, формы, карточки и мобильную навигацию; выбор хранится в этом браузере.

Кнопка «Войти как гость» находится под регистрацией и доступна также во время ожидания сервиса входа. Аккаунт для неё не требуется. Гость получает пустую историю, нулевые показатели и весь интерфейс тренировок. Гостевой прогресс хранится в localStorage, отдельно от данных аккаунтов, и сохраняется после обновления страницы. Очистка данных сайта удаляет гостевой прогресс. При недоступном хранилище приложение предупреждает, что изменения не сохранены.

В окне аккаунта гостя кнопка «Войти или зарегистрироваться» возвращает на экран входа. Гостевые данные не отправляются в D1 и не копируются в аккаунт автоматически; возвращение в гостевой режим открывает прежний локальный прогресс. Зарегистрированные пользователи продолжают работать с отдельными облачными данными.

Гостевой режим не требует почтового сервиса или серверного хеширования пароля. Офлайн-кэш загрузки самого сайта не добавлен; для первого открытия страницы нужен доступ к сайту. Одновременное редактирование гостевых данных в нескольких вкладках не объединяется — последнее сохранение заменяет предыдущую версию.

## Настройки, цель и удаление аккаунта

Настройки (шестерёнка) содержат тему оформления и отдых между подходами. Имя или ник, необязательный вес в кг и аватарка редактируются в личном профиле по нажатию на аватар. «Изменить цель» на главной открывает отдельную форму только с количеством тренировочных дней в неделю (1–7 или «Не задана»). Изменение одной формы сохраняет значения другой.

Аватар открывает окно аккаунта с выходом и удалением. Удаление доступно зарегистрированным пользователям, в том числе Google. После предупреждения нужно ввести email аккаунта и нажать «Удалить навсегда». Удаляются запись пользователя, привязки Google, все сессии, коды/ссылки подтверждения и восстановления, а также всё состояние тренировок в D1. Сервер использует текущую сессию и X-Pulse-Account, проверяет Origin и подтверждение. Новая регистрация создаёт отдельный пустой аккаунт; функции восстановления удалённого аккаунта нет. Настройка темы браузера и отдельные данные гостя сохраняются.

Перед удалением приложение останавливает отложенное автосохранение и ожидает уже выполняющийся запрос. Ошибка сохранения не блокирует намеренное удаление. Если само удаление не удалось, окно остаётся открытым с ошибкой и возможностью повтора. Гостям удаление аккаунта не предлагается. Для обновления не нужны новые секреты или миграции базы.

## Оформление кода подтверждения

Код отображается в шести отдельных ячейках. Поддерживаются ввод и исправление с клавиатуры, вставка полного кода и автозаполнение one-time-code. При неверном или истёкшем коде ячейки подсвечиваются красным и коротко встряхиваются; при редактировании ошибка сбрасывается. После успешного ответа сервера ячейки последовательно загораются зелёным, а через 0,8 секунды открывается аккаунт. Сетевые ошибки не помечают код неверным. При prefers-reduced-motion анимации отключены, цвета и текстовые подсказки сохраняются.

## Обновление с админ-панелью

Нужна миграция `0002_admin.sql`; команда `pnpm run deploy` применит её автоматически перед публикацией Worker и проверит схему. Если уже опубликованная версия выдаёт ошибку базы, выполни `pnpm run db:remote`. Не удаляй существующую базу.

После деплоя обнови страницу и войди в подтверждённый аккаунт `uvukostya@gmail.com`. Значок щита сверху открывает панель; прямой адрес — `https://pulser.pp.ua/#admin`. Другим аккаунтам API возвращает отказ. Пароль администратора не зашит в проект, дополнительные секреты для этой панели не нужны.

## Личный профиль и аватарка

Имя или ник (до 24 символов), вес (необязателен, 1–500 кг) и фото находятся в личном профиле. Фото JPG/PNG/WebP до 8 МБ и 25 мегапикселей обрезается по центру и преобразуется в JPEG 256×256 непосредственно в браузере. Перед сохранением виден предпросмотр; фото можно заменить или удалить. Изменения применяются кнопкой «Сохранить профиль». Сетевой сбой отображается штатным индикатором сохранения и кнопкой повтора.

Профиль аккаунта, включая компактную аватарку, хранится в существующей таблице fitness_state в D1; у гостя — только в этом браузере. Фото видно в верхней панели и боковом меню. Настройки и недельная цель сохраняют остальные поля профиля. Новые миграции, секреты и R2 не нужны. Поля веса и аватарки необязательны, старые профили совместимы.
